# まんがPDF

漫画のJPG画像をまとめて1つのPDFにする Web アプリ。

iPhone から数タップで、原稿を端末の外に出さずに PDF を作れる。

## 原則

この3つは今後の改修でも崩さない。

1. **利用料 0 円 / 運用費 0 円** — 静的配信のみ。サーバー・API・DB・課金サービスを一切使わない
2. **原稿を外部へ送らない** — PDF 生成はすべてブラウザ内で完結する
3. **回数無制限** — PDF を何回作っても費用が発生しない

## 依存関係

実行時の依存ライブラリは **ゼロ**。ビルドに TypeScript と Vite を使うだけ。

| | |
|---|---|
| バンドル | JS 20.5 kB / CSS 7.3 kB（gzip 合計 約 11 kB） |
| 外部通信 | アプリ本体の読み込み以外は一切なし |
| Web フォント | 使わない（システムフォントのみ） |

## 設計上の要点

### 再圧縮しない経路を最優先する

`pdf-lib` を使わず `src/lib/pdfWriter.ts` に画像専用の PDF ライタを自作している。理由は3つ。

1. **JPEG をデコードせずに埋め込める。** PDF の `DCTDecode` は JPEG をそのまま格納できるため、縮小が不要なページは画素に一切触らずに済む。`File` オブジェクトをそのまま `Blob` の部品として渡すので、原稿データが JS ヒープに載らない。画質劣化もゼロ。
2. **メモリのピークが出ない。** pdf-lib の `save()` は PDF 全体を1本の連続バッファへ展開するため瞬間的に約2倍のメモリを要求する。自作ライタは一定量ごとに `Blob` へ退避するので、使用量が増え続けない。
3. 依存が減り、バンドルが小さくなる。

### iPhone 固有の落とし穴への対処

| 問題 | 対処 |
|---|---|
| iOS Safari の Canvas 面積上限（超えると例外なしで白紙になる） | `createImageBitmap` に縮小後の寸法を渡し、原寸 Canvas を作らない。さらに `config.ts` の `SAFE_CANVAS_AREA` で上限を明示 |
| `setTimeout(0)` がバックグラウンドタブで1秒に間引かれる | `src/lib/schedule.ts` で `MessageChannel`（間引き対象外）を使う。50ページで約50秒の差になる |
| 巨大 JPEG のデコードでタブが落ちる | 原寸モードではそもそもデコードしない |
| EXIF Orientation が `DCTDecode` では再現できない | 回転が必要なページのみデコード経路へ回す（`canEmbedDirectly`） |
| CMYK JPEG の色が環境依存になる | デコードして RGB へ変換する |
| 共有シートのファイルサイズ制限 | 失敗しても保存へフォールバック。分割機能で容量を下げられる |

### ページの物理サイズ

長辺を B5（257mm）に合わせる。書き出し dpi に関係なく、印刷・提出に適した寸法になる。縦横比は保持し、トリミングはしない。横長の見開きは自動的に 257×182mm になる。

## 画質モード

| モード | 処理 | 用途 |
|---|---|---|
| **原寸**（既定） | 再圧縮なし・直接埋め込み | 劣化ゼロ。最速。印刷・提出向け |
| 高画質 | 長辺 3000px / 品質 0.92 | 容量を抑えつつ印刷にも使える |
| 共有用 | 長辺 2048px / 品質 0.85 | メールなどで送りやすい |

閾値は `src/config.ts` に集約してある。実機での確認結果に応じて調整する。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ へ出力
npm run typecheck
```

## 公開

Cloudflare Pages（無料枠・静的配信のみ）。

- ビルドコマンド: `npm run build`
- 出力ディレクトリ: `dist`
- Functions / Workers / KV / R2 / D1 は**使わない**
- 独自ドメインは購入せず `*.pages.dev` を使う

`public/_headers` に CSP を置いてある。Cloudflare Pages が自動で適用する。

## 検証済み項目

- 自然順ソート（`1.jpg` → `2.jpg` → `10.jpg`。文字列ソートの `1, 10, 2` にならない）
- 並べ替え・削除が完成 PDF に正しく反映される（埋め込みバイト列で照合）
- 縦長・横長が混在しても縦横比が崩れない
- 3モードすべてで pdf.js が正常にパース・デコードできる
- xref の全オフセットが正しいオブジェクトを指している
- PDF 生成中の外部通信が 0 件
